Enhancement Three

Databases

A safer and more efficient MongoDB layer using protected credentials, guarded writes, timeouts, projections, sorting, pagination, and indexing.

MongoDBPyMongoCRUDPaginationSecurity

Artifact description

The artifact I selected is the Grazioso Salvare Rescue Dog Dashboard that I originally created for CS 340. The dashboard uses Python, Dash, Jupyter Notebook, MongoDB, Pandas, Plotly, and Dash Leaflet. It connects to an animal shelter database and helps users identify animals that may be suitable for water rescue, mountain or wilderness rescue, and disaster or individual tracking. The results are displayed in an interactive table along with a breed chart and a map showing the selected animal’s location.

Justification for inclusion

I selected this artifact because the database is an important part of how the entire dashboard operates. The original application worked, but there were areas where the database connection, security, and query performance could be improved. This gave me an opportunity to demonstrate database skills without rebuilding the project or changing its original purpose.

One of the most important enhancements was removing the database username and password from the notebook. The original credentials were written directly in the source code, which could expose them if the project was shared. The enhanced version retrieves the credentials from protected Windows environment variables instead.

I also improved the CRUD module by adding connection timeouts, specific PyMongo error handling, and logging. Empty update and delete queries are now rejected because allowing them could accidentally modify or remove many database records. These changes make the application safer and provide clearer information when a database operation fails.

The original dashboard could request many records at once. I added database-side limits, sorting, projections, and pagination so the program retrieves only the records needed for the current table page. A compound index was also added for fields commonly used by the rescue searches. The breed chart still summarizes all matching animals, while the table loads the results in smaller groups. These improvements make the database operations more organized and efficient while preserving the same dashboard layout, filters, chart, map, and notebook launch process.

Security changes are visible in both the enhanced code and the public portfolio copy: credentials stay outside the source, and potentially destructive empty update or delete queries are rejected.

Course outcomes

This enhancement made progress toward the course outcomes I planned to address. Course Outcome 2 involves creating professional and technically sound communication. I supported this outcome by adding clearer database messages and logging that explain whether a connection or query was successful.

Course Outcome 4 involves using appropriate computing techniques and tools to create solutions that provide value. I demonstrated this by using MongoDB queries, projections, sorting, pagination, indexing, and the existing CRUD operations to improve how the dashboard accesses its data.

Course Outcome 5 involves developing a security mindset. Removing hardcoded credentials and blocking empty update and delete queries directly supported this outcome. These changes reduce the risk of exposing private information or accidentally changing large portions of the database. I met the outcome goals planned for this enhancement and do not need to make major changes to my outcome coverage plan.

Reflection

The main thing I learned from this enhancement is that a working database application can still have security and efficiency problems. The original dashboard returned the correct information, but it trusted some operations too much and could retrieve more data than the user currently needed. Adding safeguards and limiting database reads made the project more reliable without making it more complicated for the user.

The biggest challenge was improving the backend while keeping the project familiar and easy to run. I wanted the enhanced version to use the same Jupyter Notebook, dashboard layout, controls, chart, and map. I tested the final version with all 78,256 animal records and confirmed that the original rescue searches continued returning the expected results. I also tested the pagination, sorting, table filters, age filters, Reset option, chart, map, database safeguards, and secure credential configuration. This process helped me understand how database security and performance improvements can be added without overhauling an entire application.
