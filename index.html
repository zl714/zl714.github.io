Professional self-assessment

Growth through the Computer Science program

Completing the Computer Science program has changed how I think about software and technology. When I started the program, I mainly thought of programming as writing code and getting an application to work. As I progressed through my courses, I learned that computer science involves much more than that. A successful application must be understandable, secure, maintainable, and designed around the people who will use it. Developing this ePortfolio gave me the opportunity to look back at work I completed earlier in the program and recognize how much my approach has changed. I have become more comfortable working through technical problems, researching unfamiliar concepts, testing different solutions, and explaining why I made certain decisions.

My professional goal is to find a position in software development or a related computer science field, with a particular interest in the defense technology sector. I am interested in companies such as Anduril and similar organizations in or around Atlanta. This area appeals to me because it combines software engineering, data, security, and real-world problem-solving. Defense technology also requires dependable systems and careful attention to protecting information. My coursework has helped me understand that I value practical solutions, reliability, security, and continued learning. I am not expecting to enter the field knowing everything, but I now have a foundation that allows me to learn new tools, understand technical requirements, and work through problems in a structured way.

The program has also helped me improve how I communicate and collaborate. Collaboration is not limited to dividing programming tasks among a group. It also includes listening to requirements, explaining technical decisions, documenting work, accepting feedback, and making sure that a solution meets the needs of its intended users. The Grazioso Salvare dashboard demonstrates this because the application was built around the needs of an organization looking for dogs that may qualify for rescue training. The requirements had to be translated into three rescue categories, age and breed filters, an interactive table, a chart, and a location map. My code-review video also gave me experience explaining how an application works and discussing improvements in language intended for a manager, stakeholder, or classmate instead of only another programmer.

Software design and engineering have become one of the clearest areas of growth shown in my portfolio. The original dashboard worked but reviewing it later helped me recognize issues involving organization, usability, comments, error handling, and maintainability. The enhanced version uses clearer functions and comments, provides more understandable feedback when something goes wrong, includes the Grazioso Salvare logo, and has controls that behave more consistently. The Reset All option now resets the rescue category and age selections while returning the dashboard to the complete animal dataset. These improvements taught me that software engineering is not about making unnecessary changes or rebuilding an entire project. It is about identifying specific weaknesses and making focused improvements that add value without breaking existing functionality.

My work with algorithms and data structures is demonstrated through the dashboard’s filtering process. The application must take several user selections, convert them into consistent values, build the appropriate database query, and keep the table, breed chart, and map synchronized. The age filters allow information to be handled using weeks, months, or years. This required thinking about how different measurements could be converted and compared consistently. The rescue profiles also combine breed and age requirements to identify animals for water rescue, mountain or wilderness rescue, and disaster or individual tracking. Working through this logic helped me better understand how algorithms turn business requirements into repeatable steps and how design decisions can affect accuracy, efficiency, and usability.

Database development was another important part of the project. The dashboard connects Python and Dash to MongoDB through a CRUD module. The database stores animal records, while the application sends queries based on the filters selected by the user. The results are then presented through the table, chart, and map. Enhancing this portion of the project helped me understand how the database, backend logic, and user interface must work together as one system. I also improved validation and error handling so that database problems could be handled more clearly. This experience strengthened my ability to work with stored data and design applications that retrieve and present useful information to users.

Security has become a more important part of how I evaluate software. The original project included database credentials directly in the code, which may be convenient during development but creates a serious risk when code is shared publicly. The enhanced project uses environment variables so that credentials are kept outside of the source code. I also considered input validation, database errors, and the amount of technical information that should be shown to users. Preparing the project for GitHub reinforced this lesson because private credentials, local environments, cache files, and unnecessary machine-specific files had to be excluded. This helped me develop a stronger security mindset and understand that security must be considered throughout development instead of being added only after an application is finished.

Other courses also contributed to my growth. For example, my work in CS 330 required me to build and troubleshoot a three-dimensional graphics scene. That project involved transformations, textures, lighting, camera movement, and repeated testing. It was different from the database dashboard, but it developed many of the same habits, including breaking a complicated problem into smaller parts, checking the results of each change, and continuing to research when the first solution did not work. Experiences like this helped me become more patient and methodical when working through technical problems.

The items in this ePortfolio work together to demonstrate my development throughout the program. The original artifact shows my starting point, while the code review identifies areas that could be improved. The enhanced artifact demonstrates growth in software engineering, algorithms and data structures, databases, and security. The three narratives explain the reasoning behind those changes and what I learned from completing them. Together, these materials show that I can evaluate an existing system, develop a realistic improvement plan, implement focused enhancements, and communicate the results. Completing this program has not only improved my technical abilities but has also given me a clearer professional direction. I am prepared to continue learning and apply these skills in a professional environment, particularly in a position involving reliable, secure, and data-driven software.
